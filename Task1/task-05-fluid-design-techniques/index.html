Type and space that scale on their own

Not one media query in this file. Resize the window slowly — the heading above, the spacing between blocks and the container width all move continuously instead of jumping at fixed widths.

Custom properties as the single source of truth

Every colour, size and spacing step is declared once on :root. Change the value there and it updates everywhere — including inside calc() and clamp(), which plain Sass variables can't do at runtime.

clamp() for typography

clamp(min, preferred, max) — the middle value is usually a vw expression, so the browser interpolates smoothly and the outer two stop it getting silly at either extreme.

Display — clamp(2rem, 1.2rem + 4vw, 3.5rem)

Heading — clamp(1.4rem, 1.1rem + 1.6vw, 2.1rem)

Subheading — clamp(1.1rem, 1rem + 0.6vw, 1.4rem)

Body — clamp(0.95rem, 0.9rem + 0.25vw, 1.08rem)

Small print — clamp(0.8rem, 0.77rem + 0.15vw, 0.88rem)

Always keep a rem term in the middle value. A pure vw font size ignores the user's browser zoom, which is an accessibility failure.

min() and max() for widths

min() — a ceiling

width: min(100%, 60ch) reads as "60 characters, but never wider than the parent". It replaces a max-width plus a mobile override.

min(100%, 60ch)

max() — a floor

padding-inline: max(1rem, 4vw) keeps at least 1rem of breathing room on phones while letting big screens get generous margins.

max(1rem, 4vw) padding

Counter-intuitive at first: min() sets the maximum size because it picks the smaller of the two, and max() sets the minimum.

calc() for the arithmetic

calc() mixes units that otherwise can't meet — percentages with rems, viewport units with pixels — and it reads custom properties, so the maths stays in one place.

  • height: calc(100vh - var(--header-h)) — a full-height panel that accounts for the sticky header
  • width: calc(50% - var(--space-sm) / 2) — two columns that share a gutter exactly
  • padding: calc(var(--space-sm) * 1.5) — a half-step without inventing a new variable
  • --space-md: calc(var(--space-sm) * 1.5) — one variable derived from another, so the whole scale stays proportional
calc(50% - gap/2)
calc(50% - gap/2)

Spaces around the operators are mandatory: calc(100%-2rem) is invalid and silently drops the whole declaration. calc(100% - 2rem) works.

Why this beats more breakpoints

Same goal, two approaches
Breakpoints Fluid
Type jumps at 576, 768, 1024 Type moves continuously at every width
Three declarations per size One clamp()
Breaks on widths you didn't test Correct at every width by construction
New device size means new query Nothing to change

Breakpoints still earn their place for genuine layout changes — a sidebar moving beside the content, as in task 4. Use them for structure, use fluid values for size.
