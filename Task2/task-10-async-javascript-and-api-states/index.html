Async JavaScript & API States

Four states — loading, success, empty, error — each with a button that triggers it on demand. No waiting for a real failure to see the error path.

Trigger any state

Request log

Press the race button and watch the log — two requests get aborted and only the newest writes to the screen. Without that guard, a slow first request can land after a fast second one and overwrite the correct data.

The four states

State When What the user sees
Loading request in flight spinner plus skeleton rows, so the layout doesn't jump
Success data came back with items the list and a count
Empty request worked, array was empty a plain explanation — not an error
Error 404, 500, timeout, no network the reason plus a working Retry button

Empty and error are genuinely different. "No results found" is a normal outcome; "Request failed" means something broke. Merging them tells the user their data is missing when it simply isn't there.

Four things in the code worth copying

  • fetch doesn't reject on 404 or 500. It only rejects when the request never completes. You must check res.ok yourself — this is the single most common async bug.
  • AbortController for cancellation. Switching tabs aborts the previous request instead of leaving it to land later.
  • A timeout, because fetch has none. A request with no response hangs forever by default. setTimeout plus controller.abort() is the whole fix.
  • An incrementing request id. Even with aborts, guard the write: if (id !== requestId) return stops a stale response overwriting fresh data.

The shape to remember

async function load() {
showLoading();
try {
const res = await fetch(url, { signal });
if (!res.ok) throw new Error(res.status); // easy to forget
const data = await res.json();
data.length ? showSuccess(data) : showEmpty();
} catch (err) {
if (err.name === "AbortError") return; // not a real error
showError(err.message);
}
}
