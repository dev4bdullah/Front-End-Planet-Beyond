Debugging & DevTools

A sandbox for Console, Sources and Network. Several buttons break on purpose — press F12 first, or half of this is invisible.

1 · Console

After clicking, use the level dropdown in Console to filter to errors only, then warnings only. Tick Verbose to reveal console.debug.

2 · Sources and breakpoints

  • Trigger debugger — execution freezes on the debugger statement. Hover total and cart in the Scope panel, press F10 to step over each loop pass and watch total climb, then F8 to resume.
  • Step into — find team.map(build) in Sources, click the line number to set a breakpoint, click the button again, then F11 to step inside build().
  • Conditional — right-click a line number → Add conditional breakpoint → person.tasks > 10. It only pauses for Ayesha and Abdullah.

3 · Network

    Compare the three failures. A 404 returns a status and a body. An unreachable host shows (failed) with no status at all. A throttled request shows the time in the Waterfall. They are three different problems.

    4 · Errors

    In Console, click the file link on the right of any error to jump straight to the line that threw it.

    Mirrored output

    This panel is a convenience copy. The real output — with objects you can expand and stack traces you can click — is in the Console.

    Shortcuts worth memorising

    Key Does
    F8 resume execution
    F10 step over — run the line, don't go inside
    F11 step into — go inside the function being called
    Shift+F11 step out — finish this function and return
    Ctrl+P open a file by name
    Ctrl+Shift+F search across every loaded file
    Ctrl+Shift+M device toolbar
    Esc open the drawer Console from any panel

    When to reach for which

    • A value is wrong → breakpoint just before it's used, then read the Scope panel. Faster than adding console.log and reloading.
    • Data isn't appearing → Network first. Check the request fired, the status, and what the Response tab actually contains.
    • It works sometimes → conditional breakpoint on the case that fails.
    • A click does nothing → Elements → Event Listeners, to confirm the handler is bound where you think it is.
    • Something is slow → Performance tab, record, and look at the long tasks.

    console.log is fine, and every developer uses it. But it means edit, reload, repeat — a breakpoint lets you inspect every variable in scope at once without changing a line of code.
