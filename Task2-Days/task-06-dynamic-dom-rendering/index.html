Dynamic DOM Rendering

There is no task markup in this HTML file. Every card below is generated from a JavaScript array — change the data, call render(), and the page catches up.

Generated output

    render() has run 0 times — every button above changes data only.

    The pattern

    // 1. data is the single source of truth
    let tasks = [ ... ];
    // 2. one function turns one item into markup
    function taskCard(task) { return `<li>...</li>`; }
    // 3. one function writes the whole list
    function render() { list.innerHTML = tasks.map(taskCard).join(""); }
    // 4. every action changes data, then re-renders
    tasks.push(newTask); render();

    The win is that you never patch the DOM by hand. There's no code anywhere that says "find the third card and update its checkbox" — you change the array and redraw.

    Three things this does deliberately

    • escapeHtml on every value. Building markup from user input with innerHTML is an XSS hole without it. Add a task titled <img onerror=alert(1)> — it renders as text, not as a tag.
    • The empty state lives inside render(). It's just another branch of the same function, not a special case handled somewhere else that can drift out of sync.
    • Actions never touch the DOM. Every handler mutates tasks and calls render(). One code path draws the page, so there's only one place a rendering bug can live.

    innerHTML vs createElement

    innerHTML + template strings createElement
    Readability looks like the output verbose for nested markup
    Safety needs escaping — always textContent escapes for you
    Event listeners lost on redraw, so use delegation can attach per element
    Focus & scroll reset on redraw preserved if you patch in place

    This page uses innerHTML plus escaping plus delegation, which is the combination that stays readable at this size. React exists because that combination stops scaling once the app gets large.
