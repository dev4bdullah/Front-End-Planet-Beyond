ES6 Module Architecture

The same small app split across six files, each with exactly one job. Everything below is working code — the point is where each piece lives, not what it does.

Who does what

File Only thing it knows about Exports
main.js wiring and state nothing — it's the entry point
storage.js localStorage load, save, clear
api.js the network fetchTodos
render.js the DOM renderTasks, renderTodos, showError
validation.js nothing external — pure functions validateTitle, validatePriority
utils.js nothing external — pure functions makeId, escapeHtml, formatDate

    Three rules this structure follows

    • One reason to change. If localStorage becomes an API, storage.js is the only file you edit.
    • Pure files at the bottom. utils.js and validation.js import nothing, so they're trivial to test and can never cause a circular import.
    • Only main.js holds state. Every other module takes its data as an argument, which is what makes them reusable.

    The .js extension in import { load } from "./storage.js" is required in the browser. Node and bundlers let you drop it; the browser will 404.
